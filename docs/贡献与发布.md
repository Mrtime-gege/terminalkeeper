## 1. 贡献指南
> 开发与推送的硬约定见 [规范](#p3)；本文只讲怎么参与。

<a id="p1-1"></a>
### 仓库形态（先看这个）

本仓库是**发布仓库**：只包含运行时代码与文档。维护者日常开发在另一个私有仓库里，那里有完整的测试夹具、
构建与发布脚本；这些**不会**公开，也不会随 npm 包发布。

这对贡献意味着：

- **欢迎**：bug 报告、文档纠错、可复现的最小修复补丁、兼容性问题；
- **不在本仓库**：维护者的测试套件、开发工具与内部设计记录 —— 所以 PR 里不需要、也不应该附带这些；
- 涉及行为变更的 PR，请先开 issue 描述**问题与期望**，维护者会在开发仓库验证后再同步过来。

<a id="p1-2"></a>
### 提 Issue

用仓库自带的模板（Bug report / Feature request）。请附：

1. 复现步骤（命令或工具调用参数，**不要贴任何密码/令牌**）；
2. `terminalkeeper doctor` 与面板「详情 → 运行」里的环境信息；
3. 相关审计记录（可打码，但保留 `event` 与错误码）。

安全问题**不要**开公开 issue：走仓库 Security 页的私密报告（Security advisories）。

<a id="p1-3"></a>
### 代码约定

- **纯函数优先**：能放进 `lib/pure.mjs` 的逻辑不要耦合 tmux/文件系统；参数解析集中在 `lib/args.js`。
- **客户端**：`lib/client.js` 里用 `h()` 构造节点；颜色只用 `--dsw-alias-*` 主题令牌，不写死色值。
- **文案**：面向用户的提示用「人话（错误码 X）」；宿主错误码原样保留、不翻译。
- **风格**：无分号、两空格缩进、单引号；不要引入新依赖（运行时零依赖是设计目标）。

<a id="p1-4"></a>
### 文档约定

- `docs/工具与参数.md` 的第 2 部分由 `lib/param-spec.mjs` **生成**，不要手改；参数变更请改 spec 并重新生成。
- 正文面向使用者：先讲"怎么用"，再讲"边界"；不要写内部提交号、构建号、会话 id 或个人路径。
- 文档里的命令与路径必须真实可用（发布前的文档门禁会核对）。

<a id="p1-5"></a>
### 提交与 PR

- 一个 PR 只做一件事；提交信息写**为什么**，不只是"改了什么"。
- **不要改版本号**——发版由维护者统一处理（见 [发布指南](#p2)）。
- 不要在仓库里提交任何密钥、令牌、个人邮箱或本机绝对路径；维护者会在合并前跑泄露扫描。

<a id="p1-6"></a>
### 行为准则

保持技术讨论、就事论事；不人身攻击、不刷屏、不提交与项目无关的内容。

## 2. 发布指南
> 完整开发/推送约定见 [规范](#p3)；本文只讲发布流程。

本文说明 terminalkeeper 的版本策略、发布物边界与发版流程。发布由维护者执行。

<a id="p2-1"></a>
### 版本策略

- 语义化版本：`0.x` 阶段，**破坏性改动会升次版本号**（0.1 → 0.2），并在 CHANGELOG 里显式标注。
- 公开版本从 **0.1.0** 起算，不承诺对更早内部迭代版本的兼容。
- `package.json` 的版本必须与 CHANGELOG 段落、Git tag 三者一致。

<a id="p2-2"></a>
### 三条产物线

| 产物 | 内容 | 位置 |
|---|---|---|
| 开发版 | 全部代码 + 测试 + 内部文档 | 维护者本地与私有备份仓库，不公开 |
| GitHub 版 | 运行时代码 + 公开文档 + CHANGELOG + GitHub 配置 | 本仓库（独立历史，每次发布一条提交） |
| npm 版 | 仅运行时代码 | `npmjs.com/package/terminalkeeper` |

<a id="p2-3"></a>
### npm 包边界（默认不发布）

npm 包的内容是 **`package.json` 的 `files` 显式白名单**（当前 36 个文件）：

- 运行时：`lib/**`、`bin/**`、`cordis.patch.yml`、`icon.svg`；
- 辅助：`install-deps.sh`（审计加锁等系统级操作）、`purge-all.mjs`（彻底清理）；
- 元数据：`package.json`、`README.md`、`LICENSE`。

**新增文件默认不发布**。要发布新文件，维护者必须手动把它加入白名单并重新生成发布目录；
发布前的内容核对会逐文件比对真实打包结果与白名单，多一个或少一个都会失败。

不进 npm 包的内容：`docs/`、`.github/`、任何测试、内部报告、开发脚本。

<a id="p2-4"></a>
### 发布流程

1. **改版本**：`package.json` 升版本，CHANGELOG 加同版本段落（写用户可见变化）。
2. **跑门禁**（维护者在开发仓库）：
   - `npm test`：纯函数/参数/客户端/审计/订阅/文档/泄露等静态门禁；
   - **长任务测试跑两次**（真实 tmux：第一遍发现问题，第二遍在最终待发布提交上确认）；
   - `test-pack`：发布包内容门禁——真实打包清单必须与白名单完全一致；
   - 文档门禁：路径/命令真实存在、参数定义与代码一致；
   - 泄露门禁：无主机名、用户名、绝对路径、令牌、邮箱。
3. **生成 GitHub 发布目录**：只复制白名单文件 + 公开文档 + GitHub 配置，提交信息固定为 `release: vX.Y.Z`。
4. **推 tag**：`vX.Y.Z`（必须与 `package.json` 版本一致）。
5. **推 tag 即发布**：`.github/workflows/publish.yml` 在 `v*` tag push 时触发，校验 tag 与版本一致后
   通过 **Trusted Publishing（OIDC）** 发布到 npm 并生成 provenance 溯源；不需要手动 `npm publish`，
   **也不再使用任何 `NPM_TOKEN` 长期凭据**（仓库里若还留着该 secret 请删除）。
6. **（可选）GitHub Release**：在 Releases 页基于同一 tag 生成说明，方便订阅者，不参与发布。
7. **验证**：`npm view terminalkeeper version` 应为新版本；下载 tarball 确认无 `docs/`、无测试文件。

<a id="p2-5"></a>
### 发布前检查清单

- [ ] `npm view terminalkeeper version` 尚未占用目标版本号；
- [ ] CHANGELOG 有对应版本段落，且写明破坏性改动；
- [ ] npm 包白名单没有新增未审文件（逐文件看过）；
- [ ] 仓库无密钥、个人邮箱、本机绝对路径、真实主机名；
- [ ] README / 文档里的链接与命令可用；
- [ ] 旧版本（如需下线）用 `npm deprecate` 指向新版本，**不删除**已发布版本。

<a id="p2-6"></a>
### 回滚与弃用

- npm 版本内容不可修改；出问题只发新版本修复。
- 需要让旧版本停止被安装：`npm deprecate <版本> "<原因与替代版本>"`。
- 反注册（unpublish）会把包名锁定 24 小时并影响已安装用户，**只作为最后手段**。

<a id="p2-7"></a>
### 安全

- 发布物里不允许出现：真实令牌、密码、私钥、主机名、用户名、家目录路径、个人邮箱。
- 维护者在发布前必须跑泄露扫描；CI 也会对发布目录做同样检查。
- 安全问题请走私密报告渠道，不要开公开 issue。

## 3. 开发与推送规范
本文是仓库的硬约定。能自动检查的都挂在 `npm test` / `release:check` 里；本页说明**为什么**这么定，以及人工步骤。

<a id="p3-1"></a>
### 一、仓库与分支

| 仓库 | 内容 | 谁能推 |
|---|---|---|
| 开发仓库（本地 + 私有 `backup`） | 全部代码、测试、内部资料 | 维护者 |
| 公开仓库 `Mrtime-gege/terminalkeeper` | 运行时代码 + 公开文档 + GitHub 配置 | 只由发布目录推送 |

- **不在公开仓库开发**。公开仓库没有测试夹具，任何直接改动都无法验证。
- 分支：`main` 为稳定线；功能 `feat/<slug>`、修复 `fix/<slug>`、文档 `docs/<slug>`；合并前 `npm test` 必须绿。
- 发布目录（`../terminalkeeper-release`）是**生成物**：每次发布重建、独立历史，不手工编辑。

<a id="p3-2"></a>
### 二、提交规范

- 格式：`<type>(<scope>): <summary>`，`type` ∈ `feat` / `fix` / `docs` / `refactor` / `test` / `build` / `style` / `chore` / `release`。
- 正文写**为什么改、影响什么、怎么验证**；不逐行复述 diff。
- 一个提交只做一件事；**不在功能提交里改版本号**（版本只在发布提交里动）。
- 提交前自查：无密钥/令牌/个人路径；`git diff` 逐块看过。

<a id="p3-3"></a>
### 三、代码规范

- **零运行时依赖**是设计目标，新增依赖需要单独说明理由。
- 分层：纯函数进 `lib/pure.mjs`；参数解析进 `lib/args.js`；工具说明进 `lib/tool-docs.js`；面板节点用 `h()`。
- 风格：无分号、两空格缩进、单引号。
- 颜色只用 `--dsw-alias-*` 主题令牌，不写死色值。
- 面向用户的错误文案统一「人话（错误码 X）」；宿主错误码原样保留、不翻译。
- 数据目录 / 环境变量 / 插件 id 变更必须带**迁移**（复制旧数据、旧目录保留可回退）。
- **新增运行文件默认不发布**：必须手动加入 `release/publish-files.json`，否则 `test-publish-manifest` 会失败。

<a id="p3-4"></a>
### 四、消息规范

- 所有**操作反馈**（成功 / 失败 / 警告 / 引导）走 `postNotice` / `notify`：右上角消息条 + 详情「事件记录」历史。
- **不自建提示条、横幅、悬浮提示**；错误必须带错误码，方便检索。
- 页面内容（空状态文案、表单说明、能力降级说明）可以就地展示，但不得承担“临时结果提示”的职责。
- 错误边界（`PANEL_RENDER`）是唯一例外：React 崩溃时消息系统不可用，必须保留自建出口。

<a id="p3-5"></a>
### 五、文档规范

- `docs/工具与参数.md` 的第 2 部分由 `lib/param-spec.mjs` 生成，**不要手改**。
- 文档禁止出现：内部提交号/构建号/会话 id、个人路径/邮箱/主机名、测试记录、未发布的脚本路径。
- 新增公开文档要**两处登记**：`scripts/test-public-surface.mjs` 的 `ALLOWED_DOCS` + `release/manifest.json` 的 `docsInclude`。
- 文档里的命令与路径必须真实可用；`test-docs` 会核对。

<a id="p3-6"></a>
### 六、推送规范（发布）

#### 日常开发

```sh
git push backup main          # 私有备份仓库，含全部历史
```

#### 发布（唯一会碰公开仓库的动作）

```sh
# 1. 开发仓库：改版本 + CHANGELOG
# 2. 全部门禁
npm test && npm run test:longrun && npm run release:tree && npm run release:check
# 3. 发布目录：推 main（生成物，允许 --force）+ 推 tag
cd ../terminalkeeper-release
git push origin main --force
git push origin vX.Y.Z
```

- **推 `vX.Y.Z` tag 即自动发 npm**（GitHub Actions `publish.yml`），不再手动 `npm publish`。
- `vX.Y.Z` 必须等于 `package.json.version` 与 CHANGELOG 段落，否则 workflow 直接失败。
- **已发布的 tag 不移动**；发现问题发新版本。
- 回滚只用 `npm deprecate`，不 `unpublish`（会锁包名 24h 并影响已装用户）。
- 公开仓库的 `main` 由发布目录重建，允许 force push；**tag 不允许重推**。

<a id="p3-7"></a>
### 七、版本与发布节奏

- `0.x` 阶段：破坏性改动升次版本号（0.1 → 0.2），修复升修订号，CHANGELOG 显式标注。
- 每个版本必须有 CHANGELOG 段落与 GitHub Release 说明（基于同一 tag）。
- `npm publish` 前必须跑长任务测试两次：第一次找问题，第二次在最终待发布提交上确认。

<a id="p3-8"></a>
### 八、规则与门禁对照

| 规则 | 自动检查 |
|---|---|
| 新增文件默认不发布 | `test-publish-manifest`（白名单逐一比对） |
| npm 包只含运行文件 | `test-pack` + `release:check` |
| 无密钥/个人路径 | `test-leak` + `release:check` |
| 文档命令/路径真实 | `test-docs` |
| 参数定义与代码一致 | `test-param-spec` |
| 公开文档必须登记 | `test-public-surface` |
| 版本/tag/CHANGELOG 一致 | `release-check` + `publish.yml` |

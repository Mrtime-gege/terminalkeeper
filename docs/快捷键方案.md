# 快捷键方案（草案 · 未实施）

> **文档状态**：公开版本 **0.1.1**；当前行为以代码为准。


目标：借鉴 bash/readline、PowerShell(PSReadLine)、tmux 原生的键位习惯，
**不与 DSH 宿主已有的快捷键打架**，并且**让用户能自己改**。

第一版（自研 keydown：`decidePanelKey` + 面板级绑定）已经落地，
本文是把它**迁移到 DSH 快捷键服务 + 交给用户自定义**的方案。

---

## 〇、官方约定与生态现状（2026-10-05 实测）

### 1. 官方的推荐约定（`dsh-client-shortcuts/README.md` 的 Known Limitations 一节原文要点）

- **Web 上的默认值要"显式声明"，而且要克制**：`Mod+Slash`、`Mod+Backslash`、`Control+Backquote`
  保持两键组合；**不带 Alt 语义的默认用 `Mod+Alt`**，带 Alt 的用 `Mod+Shift`
  —— 例外只有两个：`fullscreen = Mod+Alt+Enter`、`session rename = Mod+Alt+G`。
- **把 `Mod+Comma` 留给浏览器**：Web 上的设置页改用 `Mod+Alt+Comma`。
- **macOS Web 故意不给"刷新当前页"绑默认键**（保住 Cmd+Option+R 的浏览器语义）。
- **Linux Web 只接受三组**：`Mod+Slash`、`Mod+Shift+Comma`、`Mod+Shift+Period`。
- `Mod` = macOS 的 Command / 其它平台的 Control；Windows 与 macOS 桌面接受"两键组合"（chord），
  **按下第一键时不延迟、不消费**（所以第一键仍可能被别的东西用掉）。
- 系统级快捷键（OS 或浏览器抢走的）**拦不到**，不要指望能绑。
- 偏好只存"覆盖项"：没改过就继承默认，`null` 表示清空；`Restore All` 只影响当前 runtime/platform。

### 2. 官方设置页实际内容（Web 环境实测，`Ctrl+/` 打开）

命令共 17 个，按**官方分组**排列：`Keyboard shortcuts / Session / Workspace / Message input /
Menus and dialogs / Approval area`。Web 上真正绑了默认键的只有这些：

| 分组 | 命令 | Web 默认键 |
|---|---|---|
| Keyboard shortcuts | Open keyboard shortcuts | `Ctrl + /` |
| Message input | Queue / Steer | `Ctrl + Enter` |
| Message input | Open reference menu | `@` |
| Message input | New line | `Shift + Enter` |
| Message input | Send message | `Enter` |
| Message input | Stop generating | `Esc Esc`（双击序列，`stopSequenceMs` 默认 500ms） |
| Menus and dialogs | Close menu or top dialog | `Esc` |
| Menus and dialogs | Move menu selection | `↑` `↓` |
| Menus and dialogs | Select menu item | `Enter` |
| Approval area | Allow once | `Enter` |
| Approval area | Reject | `Esc` |

**其余 Web 命令全是 `No shortcut`**：`New Session`、`Toggle left sidebar`、`Search sessions`、
`Add workspace`、`Rename session`、`Fork session`、`Archive session`、`Open settings`、
`Open locally`、`Toggle right sidebar`、`Workspace files`、`New terminal`、`Split`、
`Toggle panel fullscreen`、`Refresh current page`、`Close current page or window`。

> 这就是官方的真实态度：**Web 上默认尽量不绑**（浏览器/系统抢键太多），把键位留给用户在设置里按需自定。

### 3. ⚠ 修正上一节的 Ctrl+B 结论

上一节说 `Ctrl+B` 与 `sidebar.left.toggle` 冲突 —— 那是 **desktop 的默认值**。
**Web 上 `Toggle left sidebar` 是 `No shortcut`**（实测），所以：

- **在 Web（我们的主场景）里，`Ctrl+B` 没有被 DSH 占用** → 作为 tmux 前缀送终端是安全的，
  不需要改 `~/.tmux.conf`；
- 在 Desktop（Windows/macOS）上它会撞 `Ctrl+B`，那时再考虑改 tmux 前缀或让用户改 DSH 侧栏键。

同理，`Ctrl+T`/`Ctrl+P`/`Ctrl+O` 这些"桌面有、Web 没有"的组合，在 Web 上都可以放心使用。

### 4. 生态现状：除我们之外，没有插件注册快捷键

- profile 里装了 11 个第三方插件（浏览器、genui、web-search、web-all、modsearch、diff-approval、
  model-failover、ui-kit、harness-restart、lab-testkit 等），逐个扫描：
  **没有任何一个调用 `ctx.shortcuts.register/registerFixed/observeFixedInput`**；
- `dsh-browser-tool` 里的 "shortcuts" 命中只是 DOM 的 `keyshortcuts` 属性与 readability 的注释，无关；
- 官方包共 13 处注册调用（含 `registerFixed`），去重后 10 个命令（见前表）。

**结论**：快捷键服务目前基本只有官方在用，我们是第一个想接进去的第三方插件 ——
所以"照着官方约定做"就是最省事、最不会打架的路子。

## 一、调研结论

### 1. DSH 自带一套快捷键服务（这是方案的地基）

宿主客户端有两个插件：`@deepseek-ai/dsh-client-shortcuts`（注册表 / 冲突检测 / 偏好存储）与
`@deepseek-ai/dsh-client-ui-shortcuts`（键盘适配器 + 设置页卡片）。要点：

- **服务名 `ctx.shortcuts`**，插件通过它注册命令：

  ```js
  ctx.shortcuts.register({
    id: 'shell.new',                       // 唯一 id
    label: () => t('new'),                 // 设置页里显示的名字
    aliases: ['new shell', '新建终端'],     // 命令面板搜索用
    defaults: {                            // 六格：desktop/web × macos/windows/linux
      'web:windows': { code: 'KeyT', modifiers: ['primary', 'shift'] },
      'web:macos':   { code: 'KeyT', modifiers: ['primary', 'shift'] },
      'web:linux':   { code: 'KeyT', modifiers: ['primary', 'shift'] },
      // desktop:* 同理（桌面端可用更多组合）
    },
    regions: ['terminal', 'page'],         // 在哪些焦点区域生效
    modals: [],                            // 允许在哪些模态里生效
    resolve: ({ modal }) => ({ status: 'handled', run: () => { /* 动作 */ } }),
  })
  ```

- **物理键 + 修饰符**：`code` 是 `KeyA…KeyZ` / `Digit0…9` / `F1…F24` / `Comma` 等；`modifiers` 用
  `primary`（macOS 自动变 `meta`，其它平台 `control`）、`alt`、`shift`、`meta`。
- **冲突处理**：
  - 注册时与已注册命令的默认值重叠 → **直接抛错**（`Conflicting shortcut defaults`）→ 天然防止撞键；
  - 运行期若两个命令落到同一组合 → 该键被 `consume()`，返回 `blocked: conflict`，**双方都不执行**。
- **`registerFixed`**：注册"只读输入动作"，其键**不可被用户改派**，但同样参与冲突检测。
  适合"必须原样送进终端"的键。
- **Web 端允许的形态**（`isWebBindingAllowed`）：浏览器抢键很多，所以只允许
  - 修饰符 ≥ 3 个（如 `Ctrl+Alt+Shift+X`）；
  - 含主修饰符 + (`alt` 或 `shift`) 的两个修饰符组合 → **`Ctrl+Shift+X` 是允许的**；
  - 少数符号：`Ctrl+/`、`Ctrl+Shift+,`、`Ctrl+Shift+.`、`Ctrl+\`、`Ctrl+`` `。
- **终端区域的特殊放行**：Web 下当焦点在 `terminal` 区域时，`Ctrl+W` 与 `Ctrl+R` **一律放行**给终端
  （DSH 自己的规则，和"不要抢终端键"的结论一致）。
- **用户偏好存储**：Web 是 `localStorage` 的 `dsh.keybindings.v1`；桌面是 `userData/keybindings.json`。
- **设置入口已经存在**：DSH 设置 → 通用 → 快捷键（`settings.general.item` 插槽），
  支持逐项改键、冲突提示、重置。

> **结论：自定义不需要我们自己做 UI。** 我们只要"正确注册命令"，用户就能在 DSH 设置里改，
> 而且改了以后由宿主统一持久化、统一处理冲突。

### 2. DSH 已有的 10 个内置键位（必须避让）

| 命令 | 默认键 | 说明 |

### 3. 终端侧键位（借鉴对象，全部**不抢**）

  `Ctrl-K/U/W`（删到行尾/行首/删词）、`Ctrl-R`（反向搜索历史）、`Ctrl-P/N`（上/下一条）、
  `Ctrl-Y`（粘贴）、`Ctrl-L`（清屏）、`Ctrl-C/D/Z`（中断/EOF/挂起）、`Tab`/`Shift+Tab`（补全）。
- **PowerShell / PSReadLine**：`Ctrl+R`（反向历史搜索）、**`F7`**（历史列表）、`Ctrl+Space`（菜单补全）、
  `Alt+.`（上次参数）、`Ctrl+Z`（撤销输入）。
- **tmux 原生**：前缀默认 `C-b`，之后 `"`（上下分割）、`%`（左右分割）、`c`（新窗口）、
  `n`/`p`（下/上窗口）、`0…9`（直达窗口）、`z`（窗格最大化）、`o`/方向键（切换窗格）、
  `[`/`]`（复制模式/粘贴）、`x`/`&`（关窗格/关窗口）、`d`（detach）、`?`（键位表）、`:`（命令）。

### 4. 第一版已经实现的东西

- 纯函数 `decidePanelKey(e)`：`Ctrl+Shift+T/W/↑/↓/1…9/P/D/A/K/L/M` + `F2` + `Esc`；

- 613 条断言（含"终端键不被面板拦"的反向断言）+ 真机 CDP 验证。

## 二、键位设计（默认值）

> 结合第〇节的官方约定，**默认值要克制**：官方在 Web 上给大多数命令留空。建议我们只给
> **2–3 个真正高频**的绑定默认值（全局开合面板、上一个/下一个 shell），其余命令**注册但默认不绑**
> （在设置页里显示 `No shortcut`，用户想用自己绑）。若要给默认，形态优先 `Mod+Alt+*`
> （避开 `Mod+Alt+Enter`、`Mod+Alt+G`、`Mod+Alt+Comma` 这三个官方已用/保留项）。


原则：**面板只用 `Ctrl+Shift+*`**（DSH 认可的 Web 形态；且与上面 10 个内置键位零冲突），
**终端键一律不动**。

| 动作 | 默认键 | 与 DSH 内置对照 |
|---|---|---|
| 新建 shell | `Ctrl+Shift+T` | `browser.new` 是 `Ctrl+T`（无 Shift）→ 不冲突 |
| 关闭当前 shell | `Ctrl+Shift+W` | 无占用（且 Web 终端区 `Ctrl+W` 本身就被放行） |
| 上一个 / 下一个 shell | `Ctrl+Shift+↑ / ↓` | 无占用 |
| 跳到第 N 个 shell | `Ctrl+Shift+1…9` | 无占用 |
| 会话选择器 | `Ctrl+Shift+P` | `workspace.files` 是 `Ctrl+P` → 不冲突 |
| 详情 | `Ctrl+Shift+D` | 无占用 |
| 授权管理 | `Ctrl+Shift+A` | 无占用 |
| 引用库 | `Ctrl+Shift+K` | 无占用 |
| 日志管理 | `Ctrl+Shift+L` | 无占用 |
| 锁定 / 解锁 | `Ctrl+Shift+M` | 无占用 |
| 重命名当前 shell | `F2` | 无占用（tmux 里是 `,`） |
| 面板内搜索 | `Ctrl+F` | 无占用（当前已接管浏览器查找） |
| 关闭浮层 | `Esc` | `approval.reject` 是固定 `Esc` → **见下** |

## 二·补：分层捕获模型（推荐方案，回答"只捕获焦点在我们面板时"）

用户提的原则：**焦点在我们面板里才由我们管快捷键，其余全放给 DSH，另外保留一个全局开关键。**

### 结论：能，而且是 DSH 机制的正解

`ShortcutCommand.regions` 只接受三个值，`ShortcutContext` 会带上**原始输入元素**：

```ts
type ShortcutRegion = 'page' | 'editable' | 'terminal'
interface ShortcutContext { region: ShortcutRegion; modal: string | null; target: Element | null }
```

所以分两层：

1. **面板内的快捷键** → `regions: ['editable', 'page']`，然后在 `resolve(context)` 里判断
   `panelRef.current.contains(context.target)`：
   - 在面板内 → `{ status: 'handled', run: ... }`
   - 不在面板内（比如焦点在 DSH 聊天输入框）→ **`{ status: 'pass' }`**，原样交给 DSH 与浏览器。

   `resolve` 能返回 `pass` 是关键 —— 它让"同一组合、按焦点位置决定归谁"成为可能。
2. **全局开合面板** → 单独注册一个命令，`regions: ['page', 'editable', 'terminal']` 全含，
   `resolve` 无条件 `handled`；并声明 `modals` 覆盖常见模态（否则模态里会被 `blocked`）。

### ⚠ 实施时最大的坑：我们拿不到 `terminal`

`region` 的真实判定（`dsh-client-shortcuts/lib/client.js:780,906`）：

```js
const region = element?.closest('.xterm') ? 'terminal'
  : element?.closest('input, textarea, select, [contenteditable="true"], [contenteditable=""]') ? 'editable'
  : 'page'
```

**`terminal` 只认 xterm.js 的 `.xterm` 子树**。我们的面板是 tmux + 自绘输入行，**不是 xterm** →
焦点在我们的输入行时 region 是 **`editable`**，在按钮/表格上时是 **`page`**，永远不是 `terminal`。

推论：

- 不能靠 `regions: ['terminal']` 来"只管自己" —— 必须写 `['editable','page']` + 上面那条 `target` 判定；
- 同理，DSH 给 terminal 区域的 `Ctrl+W`/`Ctrl+R` 豁免规则**对我们不生效**（`dispatch` 里只在
  `region === 'terminal'` 时放行）→ 这两个键得靠我们自己的输入框处理（见下面的"顺带发现"）。

### 全局开关的建议键位

| 候选 | 说明 |
|---|---|
| **`Ctrl+Shift+/`**（`primary+shift+Slash`） | DSH 只占用了 `Ctrl+/`（`shortcuts.open`），无冲突；Web 允许（primary+shift 两修饰符）→ **推荐** |
| `Ctrl+Shift+\`` | 与 `terminal.new`（`Ctrl+\``）不冲突，但语义容易混 |
| `Ctrl+Alt+P` | 可用，但三键组合记忆成本高 |

### 冲突预检（避免"按了没反应"）

`Shortcuts.describeBinding(binding)` 会返回该组合的 `issue` 与 `conflicts`（重叠的 editable/fixed 命令 id）。
所以注册前可以**先探测再决定**：

- 若目标组合已有冲突 → 不注册该键（保留动作，让用户在 DSH 设置里自己绑），并在插件里提示；
- 这样不会出现"注册即报错"或"两方都被吞掉"的情况。

### 顺带发现：`Ctrl+W` 现在会关浏览器标签页（建议一起修）

我们输入框的 `CTRL_KEYS` 目前是 `a b c d e f k l p r u y z` —— **没有 `w`**（也没有 `n`/`h`/`i`/`m`）。
而 readline 的 `Ctrl+W` 是"删掉前一个词"，DSH 的 terminal 豁免又管不到我们（见上），
所以现在按 `Ctrl+W` 很可能被**浏览器拿去关标签页**。建议把 readline 剩下的常用键补齐
（`Ctrl+W` 删词、`Ctrl-T` 交换字符、`Ctrl-H` 退格）；这不是快捷键功能的一部分，但属于同一条
"终端键不该被抢"的规则。

### 这一层的实施顺序（替代第四节 1–2 步）

1. 真机先验证假设：临时注册一个 `regions: ['editable','page']` 的命令，确认
   (a) 焦点在输入行时 `region === 'editable'`、在面板按钮上时 `=== 'page'`；
   (b) `context.target` 确实是输入元素（能用于 `contains()` 判定）；
   (c) 焦点在聊天输入框时我们**不**被触发。
2. 按验证结果注册：12 个面板命令（`['editable','page']` + `target` 判定）+ 1 个全局开合（三区域全含）。
3. 保留现有 `decidePanelKey` + keydown 作为**降级路径**（服务缺失或探测失败时行为不变）。

## 三、需要拍板的三个冲突

### ① `Ctrl+B`：tmux 前缀 vs DSH 左栏开关（**最重要**）

现状：我们把 `Ctrl+B` 原样送终端 → tmux 前缀可用；但 DSH 的 `sidebar.left.toggle` 也绑了
`Ctrl+B`。而 DSH 的规则是"重叠 → 两边都不执行"，所以**实际表现取决于适配器与输入框谁先收到**，
并且很可能变成"按了 Ctrl+B 既不开栏、也不进 tmux"。

三个选项：

- **A（推荐）改 tmux 前缀**：`~/.tmux.conf` 里 `set -g prefix C-a` + `bind C-a send-prefix`
  （`Ctrl+A` 在 Web 上 `isWebBindingAllowed` 也放行，且 DSH 没占用；只要避开 readline 的
  `Ctrl-A`（行首）——tmux 只在面板内生效，冲突面很小）。
- **B 让用户改 DSH 侧栏键**：因为 DSH 支持自定义，用户可在设置里把 `sidebar.left.toggle`
  改成别的（如 `Ctrl+Alt+B`）→ 我们不抢、只给指引。
- **C 维持现状 + 文档说明**：在键位表里标注"`Ctrl+B` 与 DSH 侧栏同键，二者会互相干扰"，
  把选择权交给用户（最省事、但体验不稳定）。

### ② `Esc`：关浮层 vs 审批拒绝 / `Esc Esc` 停止生成

`approval.reject` 是**固定键**（不可重绑）。我们的 `Esc` 只在"有浮层打开"时拦截，
且只作用于我们自己的面板内；审批弹窗是 DSH 的模态 → 用 `modals: []`（不允许在我们的浮层
之外的模态里生效）就能彻底避开。建议保留现在的行为，注册时明确 `regions: ['terminal','page']`、
`modals: []`。

### ③ `Ctrl+F`：面板内搜索 vs 浏览器查找

已接管（浏览器查找被 `preventDefault`）。这是有意为之：终端里的 `Ctrl+F` 是 readline 的"右移一字符"，
但方向键可以做同样的事；而"面板内搜索"没有更好的键位。**如果用户更想要终端语义**，
正好可以通过 DSH 设置把它改掉（我们把默认值给 `Ctrl+F`，用户可清空绑定 → 键就回终端）。
这是"可自定义"带来的好处，建议保持。

## 四、迁移路径（自研 keydown → `ctx.shortcuts`）

1. **能力探测**：客户端半边启动时探测 `ctx.shortcuts`（Cordis 里 `ctx.shortcuts` 不存在时为
   `undefined`）→ 有就用服务注册，没有就**保留现有 `decidePanelKey` + keydown 绑定**作为降级路径
   （老宿主仍可用，行为与今天一致）。
2. **注册命令**：把上表 12 个动作用 `ctx.shortcuts.register` 注册，默认值 = 今天的键位；
   `label`/`aliases` 写中文 + 英文，便于命令面板搜索与设置页阅读；`regions: ['terminal', 'page']`，
   `modals: []`。
3. **不要用 `registerFixed` 抢手场面板键**：`registerFixed` 适合"必须原样送终端的固定输入键"。
   面板动作是可自定义命令，应该可改绑；用 fixed 反而会被冲突吞掉且不可改。
4. **键位表改为"读目录"**：详情页的键位表从 `ctx.shortcuts` 的目录（catalog）生成，
   而不是硬编码 —— 这样用户改键后，键位表显示的也是**他实际在用的键**（现在会显示默认值，会骗人）。
5. **保留纯函数**：`decidePanelKey` 继续保留并测试（降级路径用），另外把"动作 id"抽成
   两种路径共用的映射，避免两套逻辑漂移。
6. **验证**：真机上打开 DSH 设置 → 通用 → 快捷键，确认我们的命令都出现、能改、改完生效、
   与内置项无冲突告警。

## 五、用户自定义：能力与边界

- **能力**：改键（包括清空）、冲突提示、一键重置；Web 存 `dsh.keybindings.v1`，桌面存
  `userData/keybindings.json`；跨平台默认值按 `desktop/web × macos/windows/linux` 六格给。
- **我们不该做的**：不要自建一套键位存储（会和宿主的偏好文档打架）；不要用 `preventDefault`
  抢 DSH 已注册的键（会被宿主 consume，双方都失效）。
- **要补的**：给每个命令写清 `label` 与 `aliases`；在插件 README 里附上"默认键位 + 怎么改"。

## 六、建议的实施步骤

2. 客户端半边加 `ctx.shortcuts` 探测 + 12 个命令注册（默认值同今天），保留 keydown 降级。

6. 文档：README「界面设计」补一节"快捷键（默认 + 自定义入口）"。

## 七、结论建议：不做全量快捷键，只做必要的（用户追问后的取舍）

问："是不是我们不做快捷键更好，或者只做几个必要的？" —— **答：是。建议只保留必要的，不做 12 个面板命令的全量绑定。**

### 为什么全量不划算

1. **官方在 Web 上自己都几乎不绑**：17 个命令只有 9 个键位（`Ctrl+/`、`Ctrl+Enter`、`@`、
   `Shift+Enter`、`Enter`、`Esc Esc`、`Esc`、`↑↓`、`Enter/Esc`），其余全是 `No shortcut`。
   这不是官方偷懒，而是 Web 环境键位稀缺（浏览器与系统先抢）。
2. **我们的动作是低频的**：新建 shell、看日志、改授权，实际使用是一天几次量级；
   鼠标"点按钮 → 看列表 → 点行"虽然多两步，但**不需要记忆**，而 12 个键需要用户先学会。
3. **每个键都有成本**：跨 `desktop/web × macos/windows/linux` 六格声明默认值、跨浏览器验证
   实际投递（官方 README 明确写"browser or system delivery requires platform testing"）、
   还要与官方 10 个命令做冲突预检。键位越多，这堆成本线性增长。
4. **可发现性差**：面板 UI 是自解释的（按钮、菜单、列表带文案），快捷键不做键位表就没人知道；
   而键位表本身又要跟着 catalog 维护。

### 建议保留 / 新增的（按必要性排序）

| 项 | 类型 | 实际频率 | 建议 |
|---|---|---|---|
| readline 键透传补齐（`Ctrl+W`/`Ctrl+H`/`Ctrl+T`） | **bug 修复**，不是快捷键功能 | 高 | **必修** —— 现在 `Ctrl+W` 会被浏览器拿去关标签页 |
| `Esc` 关浮层 | 面板内（自研 keydown） | 中 | **保留** —— 但有浮层才 consume，别弄断官方 `Esc Esc` 停止生成 |
| `Ctrl+F` 面板内搜索 | 面板内 | 中 | **保留** —— 已接管浏览器查找 |
| `F2` 重命名当前 shell | 面板内 | 低 | 保留（已实现，零额外成本） |
| **面板开合** | **全局** | 高 | **建议只做这一个进 `ctx.shortcuts`**：唯一真正需要"焦点不在面板也能用"的动作；注册后用户可自定义、官方帮做冲突检测 |
| 上一个 / 下一个 shell | 面板内 | 中（多 shell 时才高） | 可选，可有可无 |
| 新建 / 关闭 / 详情 / 授权 / 引用库 / 日志 / 锁定 | 面板内 | 低 | **不做** —— 点击更快，注册了也没人用 |

### 最小方案（推荐）

**修 1 个 bug + 保留 3 个面板内键 + 最多 1 个全局键。**

- 成本几乎为零：不新增需要记忆的键；
- 无冲突风险：只注册 0–1 个命令，冲突面极小；
- 用户想加：设置页里命令已在（若注册），他自己绑。

> 换句话说：**不是"实现快捷键功能"，而是"把该给终端的键还给终端，再留一个开合面板的口子"。**

## 附：为什么不让插件自己抢键

自研 `keydown` 有三件事做不好，而 DSH 的服务都替我们做了：

1. **看不见别人的键位** —— 自研只能"我监听、我先拦"，撞上 `Ctrl+B` 这类内置键就会互相干扰；
   服务能在注册时直接报冲突。
2. **用户改不了** —— 自研的键位写死在插件里；服务的键位天然出现在设置页，还能持久化。
3. **焦点/模态判断容易错** —— 服务有 `regions`（`page`/`editable`/`terminal`）与 `modals`，
   并且 Web 下对终端区的 `Ctrl+W`/`Ctrl+R` 有统一豁免规则，自研要实现这些细节很容易漏。

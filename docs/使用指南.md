## 1. 使用细节
> 参数的**权威定义**见 [工具与参数](工具与参数.md#p2)。
> 本文只讲「怎么用、要注意什么」，不复述实现。

<a id="p1-1"></a>
### 1. 它是什么

一个 DSH 插件：私有 tmux 服务端持有若干**持久 shell**，关页面 / 换对话 / 热重载 / 重启 DSH 都不丢；
另有 7 个模型工具、一个给人用的备用 `/tk` 纯文本命令、一个真终端面板、一条可检测篡改的审计链、一个只能由人写入的引用库（vault）。

<a id="p1-2"></a>
### 2. 安装、升级、卸载

```sh
npx -y terminalkeeper install [--profile web]   # 登记进 profile、装依赖、检查 tmux
npx -y terminalkeeper doctor                    # 体检
npx -y terminalkeeper uninstall                 # 反向移除（数据保留）
```

- 装完/升级后优先**重启一次 `dsh web`**；之后如果只是插件页面/客户端更新，刷新页面或等热重载即可。
- 彻底清理：`node purge-all.mjs`（默认 dry-run）→ 确认后加 `--yes`；或 `npx -y terminalkeeper purge-data --dry-run/--yes`。
- 备份/恢复：`terminalkeeper backup` / `restore`（默认落在 `$HOME`，不会写进插件安装目录）。

<a id="p1-3"></a>
### 3. 配置

两种入口：**设置页**（面板 ⚙，7 个分区）与 `cordis.patch.yml` 的 `config`。设置页写入的覆盖值优先。
分区：功能开关 / 终端与会话 / 界面与外观 / 面板与显示 / 审计与留痕 / 安全 / 服务端与集成。

常用项与默认值：

| 键 | 默认 | 说明 |
|---|---|---|
| `shell` / `shellArgs` | `bash` / `[]` | 新会话用的 shell 与参数（写进 tmux 服务端配置，改了要重启） |
| `cols` / `rows` | 120 / 32 | 新会话尺寸（范围 20–1000 × 5–500） |
| `historyLimit` | 100000 | 每会话保留的历史行数（改了要重启） |
| `maxSessions` | 8 | 全局存活上限（1–64）；超出后新建整批拒绝 |
| `idleClose` / `idleCloseMinutes` | `false` / 60 | 空闲自动回收总开关与兜底分钟数 |
| `guardDangerousCommands` | `true` | 危险命令守卫（启发式，不是沙箱） |
| `vaultAutoLockMinutes` | `10` | 口令组闲置多少分钟自动锁定，0–2880；0 = 不自动锁定 |
| `maintenanceIntervalSeconds` | `10` | 后台维护扫描间隔（秒，1–60）：统一跑死壳/闲置/过期/自动锁定 |
| `redactSecrets` | `true` | 输出打码 |
| `audit` / `auditRetentionDays` | `true` / 30 | 审计链与保留期 |
| `captureOutput` | `true` | 终端输出留痕（默认上限 64 MiB/会话） |
| `replayCapture` | `true` | 屏幕帧回放录制（占磁盘，可关） |
| `panelPollMs` | 800 | 面板轮询节奏（有 SSE 推送时只作兜底） |
| `allowedHosts` | `[]` | 面板 HTTP 允许的额外 Host（默认只认回环） |

**清理执行二次确认**：设置页的「立即执行」第一次点击只进入确认态，第二次才真正按策略删除/轮转文件；API 上对应 `action:'apply', confirm:true`。

**安全项二次确认**：`guardDangerousCommands` / `audit` / `redactSecrets` / `auditDir` / `allowedHosts` / `shell` / `shellArgs` 等影响安全边界的项，值变化时第一次保存会被拒绝（409 `needConfirm`），再保存一次即确认；`auditDir` 必须是绝对路径且不能含 `..`。

**立即生效 vs 重启**：改尺寸、空闲、审计、开关、面板外观等下次调用/渲染即生效；
`shell` / `shellArgs` / `defaultTerminal` / `historyLimit` / `extendedKeys` 写在 tmux 服务端配置里，**必须重启 dsh** 才重建服务端。

<a id="p1-4"></a>
### 4. 面板（人这一侧）

右下角胶囊 `>_ N 🔒`：N 是会话数，🔒 表示当前锁着（点一下解锁即可直接打字）。

- **列表**：排序 / 多条件筛选 / 批量操作（重开、统一尺寸、锁定、关闭）/ 台账。
- **终端**：真终端（`sudo`、`vim`、REPL、补全、历史全通）；抓屏 SSE 推送，断线自动退回轮询；
  面板内搜索 `Ctrl+F`（`Aa` 区分大小写、`.*` 正则、`◐` 按文字/背景颜色 + 目标色与容差）；`Ctrl+Shift+↑/↓` 切换会话；`F2` 改名；`Esc` 关浮层（没有浮层时按键照常送给终端）。
  完整键位见 [键位](#p3)。
- **详情（8 个页签）**：总览 / 概览 / 运行 / 安全 / 事件记录 / 引用库事件 / 日志审计 / 键位帮助。
  总览看状态与指标；运行看启动流程与参数；安全看模式闸门、审计链、镜像和引用库状态；后三个页签是记录与帮助。
- **锁**：面板锁定后，AI 对该会话的**写操作**一律 `REFUSED`（不会等待）；只读查询不受影响。

<a id="p1-5"></a>
### 5. 工具（AI 这一侧）

**插件不提供对话授权页面或按对话规则**。是否能用写工具由 DSH 的沙箱模式决定：完全控制（`danger-full-access`）下直接可用；工作区/只读模式下改动类工具会被模式闸门拒绝。只读工具（`shell_state` / `shell_read` / `shell_audit`）始终可用。

所有工具共用 `{ tasks: [{ target, action, wait, output, safety }] }` 结构：

- `target.sessions`：`mine`（本对话创建的全部 shell）/ `*`（全部存活）/ 具体 id（逗号分隔）。
- `action.kind`：一个任务只做一件事；**同一个 shell 在一次调用里只能出现一次**（重复直接整次拒绝）。
- 参数含义与默认值：见 [工具与参数](工具与参数.md#p2)。

| 工具 | 用途 |
|---|---|
| `shell_open` | 开持久 shell（label/cwd/cols/rows/idleMinutes/watch/from） |
| `shell_run` | 跑命令：`run`（配 command）/ `steps`（短交互序列）/ `retry` |
| `shell_send` | 像人一样输入：`preKeys → text → keys`（text 不自动回车） |
| `shell_read` | 读屏幕/历史/增量；`subscribe` / `unsubscribe` 订阅新输出 |
| `shell_manage` | 生命周期与资源：rename/resize/respawn/close/reap/idle/snapshot(-list)/doctor/宏/工作区/vault-list；`action.kind=help` 可按功能块查看说明 |
| `shell_state` | 看会话状态与归属（只读，扁平过滤参数） |
| `shell_audit` | 读审计链（按 actor/source/days 过滤，可 export） |

**长任务的推荐流程**（异步启动 → 期间读增量 → 事后取退出码）：

```jsonc
// 1) 开
{ "tasks": [{ "action": { "kind": "open", "label": "build", "cwd": "/repo" } }] }
// 2) 异步启动（立即返回，返回里带 run=<id>）
{ "tasks": [{ "target": { "sessions": "dsh-ab12cd" },
              "action": { "kind": "run", "command": "make -j8" },
              "wait": { "kind": "none" } }] }
// 3) 期间读增量（不要读整屏）
{ "tasks": [{ "target": { "sessions": "dsh-ab12cd" },
              "action": { "kind": "read", "mode": "since" } }] }
// 4) 结束后取退出码（runId 绑定到第 2 步那次运行）
{ "tasks": [{ "target": { "sessions": "dsh-ab12cd" },
              "action": { "kind": "read" },
              "wait": { "kind": "exit", "runId": "ab12cd34", "timeoutMs": 180000 } }] }
// 5) 关
{ "tasks": [{ "target": { "sessions": "dsh-ab12cd" }, "action": { "kind": "close" } }] }
```

**三个必须知道的坑**：

1. 命令里**不要写 `exit`** —— 它结束的是 shell 本身，退出码标记就永远不会出现；需要提前返回用子 shell `( … )`。
2. 含 `{{v:…}}` / `{{m:…}}` 的命令**不会**被包装（拿不到退出码标记）：要退出码用 `wait.kind="idle"`，或包一层 `sh -c "…"`。
3. 同一 shell 在一次调用里重复出现 = 整次拒绝；多任务请拆成多次调用。

<a id="p1-6"></a>
### 6. 引用库（vault）

**只有人能写**：面板「🔑 引用库」、CLI 或输入栏的 `/tk vault key set`；AI 的工具面没有写入入口，默认只看到键名。`/tk` 是给人用的宿主命令，命令文本和结果会进入会话，因此值只能通过 0600 文件传入。

> **先记住边界**：引用库只防止敏感值**直接进入模型上下文**，不防拿到 shell 的 AI 主动读取。它适合降低“顺手把密码贴进对话”的风险，不是秘密隔离。

- **组**：新键默认落在「默认引用组」。默认组新库默认只存内存（`vaultPersist` 可改为明文落盘）；每组三种模式：不加密 / 简单混淆（设备密钥，只防明文被全盘搜到）/ 口令加密（需要口令解锁）。
  口令组用 `scrypt` 派生密钥，再加设备 `pepper`（32 字节随机值，存在 `vault.pepper`）：**只拿到 vault.json、没有 pepper 时无法直接用密文离线猜口令**。
  pepper 和 vault.json 在同一数据目录，同权限 AI 仍可读；备份时必须把 `vault.pepper` 和 `vault.json` 一起保存，丢失 pepper 会让口令组永久无法解密。
  **口令模式的上限**：未解锁时磁盘上只有密文，插件不会自动解密；用户解锁后，宿主内存里会有 KEK，本机同源接口和同权限进程不再被这层保护挡住。
  **自动锁定**：口令组在最后一次解锁或单键取值后闲置 10 分钟自动锁定（可在设置中改为 0 = 关闭）；自动锁定不改变“同用户 AI 仍可能主动读取”的边界。
  **锁定组**：不列键名、不能引用、不能迁移或删除；先在组那一行点「解密」，或执行 `/tk vault group unlock <name>`。
- **条目**：值 / 类型（`secret` 等）/ **剩余可用次数** / 有效期至 / 备注。
  - 剩余可用次数是**输入框**（不再是复选框）：填 N = 还能再用 N 次；**1 = 一次性**（用掉即焚）；留空 = 不限。

  - 额度用尽会自动销毁该键，并留下**烧伤标记**；重建同名键需要显式确认（面板/接口用 `reuseName:true`，`/tk` 用 `--reuse`）。
  - **改值不重置已用次数**（次数是托管额度，不是值的属性）。
  - 有效期至：到点自动焚毁；留空 = 永不过期。
- **AI 的用法（严格）**：AI 只能做**整条裸引用** —— 整条输入就是 `{{v:键名}}`（典型是 `shell_run` 的 `steps[].send`，
  把值直接喂给程序的标准输入提示，如 `read -s pw` / `sudo -S`）。
  `shell_manage action=vault-list` 只回**键名 + 额度/已用次数**，永远不含值。
  面板的 `GET /vault-list` 也不返回值；要取某个值，可以在面板点该行「复制值」（单键 `POST /vault-get`），或用 `/tk vault key get <key> --to-file PATH --yes` 导出到 0600 文件；两种读取都记审计。
  **AI 的 shell 若访问本机接口，同样可以按单键读取**；同源脚本也能逐个取。这是“防直接进上下文”，不是“防主动读取”。
  **把 `{{v:键名}}` 嵌进命令**（`curl -H "…{{v:key}}"`、`echo`、管道）会被直接拒绝：值一旦进 AI 可加工的管线，
  任何变换输出（base64/rev/od）都能绕过打码（转换外泄，实测）。需要的话由人在面板「引用库」旁亲自输入。
  宏由人写时可嵌 `{{v:}}`（宏体全量入链）；AI 写的宏展开时同样按裸引用规则校验。
- **打码边界（诚实说明）**：输出里出现值会被打码，但**加工管道能绕过**（`base64`/`rev`/`od` 等变形成非字面值），
  `output/` 留痕是原始字节流，值进过屏幕就会进留痕；同权限进程能直接读 `vault.json` / `vault.pepper`（0600 只挡别的用户）。
  要真正保密，唯一办法是别把重要凭据交给 AI 可达的 shell。
- CLI：`terminalkeeper vault list|set|rm`（写入的是同一份 vault.json）。

<a id="p1-7"></a>
### 7. 宏（可复用的命令片段）

- 存：`shell_manage action=macro-set`（`name` / `text` / `scope=global|conversation|shell` / `submit`），或 `/tk macro set <key> --text-file PATH [--scope …] [--no-submit]`。
- **用**：在 `shell_run` 的命令里写 `{{m:宏名}}` —— 直接把宏名当命令敲**不会**执行。
- `submit:true` 表示展开后自动回车；宏里可以嵌 `{{v:…}}`（但含引用的宏展开后同样拿不到退出码标记）。
- 所有宏写入、修改、还原都会进审计链。
- **AI 侧不能创建或展开含 `{{v:…}}` 的宏**（会绕过「只能整条裸引用」）；这类宏只能由人在面板或 `/tk macro set` 里创建。
- **多行值不能作为裸引用注入**：换行会被 shell 拆成多条命令（实测第二行会被执行）；多行内容请手动复制，或存成文件后引用路径。
- **裸引用不是保密边界**：把值喂给会回显的程序（如 `cat`）仍会让值出现在屏幕上；打码只覆盖“引用注入产生的行”，程序自打的明文按已泄露对待。
- **单值上限 16 KiB**：密码、令牌、PEM/证书、环境变量块都够用；更大的内容请加密落文件，用路径引用。
- **总量上限**：总键数 2000、每组 500 键、明文总量 5 MiB；超限时写入返回 400（防误导入撑爆 vault/备份）。

<a id="p1-8"></a>
### 8. 工作区与快照

- **工作区**：`workspace-save name` 存一组会话布局；`workspace-list` 查看；`workspace-restore name` **会新开 shell**（不是原地恢复）；`workspace-delete name` 删除。`/tk` 对应 `workspace save|list|restore|delete`。
- **快照**：`snapshot` 手动存（按会话 id）；`snapshot-list` 列出已有快照；`shell_open { from: "<旧会话 id>" }` 复活。`/tk shell snapshot <id>` 与 `/tk shell snapshot-list` 等价。
  `close` / 空闲回收 / `resize` / `rename` 也会**自动留快照**（reason 字段注明），但只恢复屏面与历史，**不恢复进程**。

<a id="p1-9"></a>
### 9. 审计与留痕

- 每天一个文件：`<数据目录>/audit/audit-YYYY-MM-DD.jsonl`，逐条封链（SHA-256 串接）。
- 工具调用、`/tk` 文本命令、每次送进 shell 的输入、会话生命周期、设置变更、宏写入、手动删除（purge）都在里面。
- 审计记录的 `source` 常见值：`tool` / `panel` / `tk` / `host` / `cli` / `settings`；过滤按精确值匹配。
- 审计链会周期性生成**签名检查点**，可配镜像目录异地保存；断链 / 改字节 / 调顺序都会被发现。
- 终端输出留痕是另外的 `output/*.log`（原始字节流，容量可配），close 时把 `sha256+bytes` 写进审计。
- 查看：面板「日志审计」页签 / `shell_audit` 工具 / `terminalkeeper verify-audit <目录>` / `purge-audit`（删除会入链见证）。
- 审计时间戳按 **UTC** 显示（末尾 `Z`）；`shell_audit` 的 `output.lines` 是**返回记录条数**（默认 50、最大 500，取最后 N 条），更早记录仍在链上，可调大 `lines` 或用 `export:true` 导出。

<a id="p1-10"></a>
### 10. HTTP API（面板用的那套）

路由挂在 `/plugins/shell/*` 下，**没有独立鉴权**，防线是 DSH 的浏览器会话 + 本地围栏（Host 必须回环、拒绝跨站、写请求必须 `Content-Type: application/json`）。
被拒的请求会记进面板「闸门拒绝」。

路由一览（按用途）：

- 会话：`/list` `/new` `/kill` `/rename` `/resize` `/respawn` `/screen` `/stream` `/keys` `/busy` `/lock`
- 其它：`/settings` `/status` `/diagnose` `/probe` `/notice` `/debugctl`
- 审计：`/audit` `/audit-files` `/audit-size` `/chain` `/supervisor` `/panel-retention`
- 回放：`/replay` `/replays`
- 宏：`/macro-list` `/macro-set` `/macro-rm`
- 引用库：`/vault-list` `/vault-get` `/vault-set` `/vault-rm` `/vault-groups` `/vault-group-set` `/vault-mode` `/vault-move` `/vault-lock` `/vault-unlock` `/vault-devkey` `/vault-history`

<a id="p1-11"></a>
### 11. 什么时候需要重启

| 情况 | 要做的事 |
|---|---|
| 面板页面、按钮之类的更新 | 刷新页面，或等面板自动热重载 |
| 插件后台逻辑更新 | 通常会自动热重载；没生效再重启 `dsh web` |
| 升级插件版本 | 装完后重启一次 `dsh web` 最稳 |
| 改了启动方式、systemd scope 等服务配置 | 重启 `dsh web` |
| 改了 `shell`/`shellArgs`/`historyLimit`/`extendedKeys` | 重启（要重建 tmux 服务端） |
| 面板提示「DSH 的代码比面板旧 / 面板比 DSH 旧」 | 重启 `dsh web` |

<a id="p1-12"></a>
### 12. 已知限制（不假装能挡）

- 引用库不是同用户隔离：同权限进程可读 `vault.json`；口令组未解锁时见到的是密文，解锁后不再受这层保护；值进过屏幕就会进留痕。
- 值经加工管道可被 AI 还原（base64/rev 等）——计数只能限制次数，挡不住第一次。
- 危险命令守卫是启发式减速带：它拦根/家/通配删除、`mkfs`、`dd` 写块设备、`curl|sh`、`tmux kill-server`、`npm publish`、`git push --force` 等，**`rm -rf /tmp/x` 这类普通清理不拦**。
- 订阅只适合行式输出；`top`/`vim` 这类全屏 TUI 订阅只会得到重绘噪音（用 `read` 读当前屏）。
- 服务绑到 `0.0.0.0` 时本地围栏无法判断是否本机（DNS rebinding 面），面板会明确标出降级。

## 2. 输入栏 `/tk` 命令（备用）

> **日常操作请优先使用右下角面板和设置页。`/tk` 是备用通道，仅用于面板打不开、远程/无浏览器、CLI/TUI、恢复与排障等场景，不推荐作为主要操作方式。**

`/tk` 是插件注册的**唯一**宿主命令（`ctx.commands`），Web 输入栏与提供该适配器的 CLI/TUI 共用同一套语法。**命令和结果都是纯文本，进入会话文本流；不打开面板或其它 Web 结果界面。** 它不是面板的等价替代：功能更少，且命令文本会进入模型上下文。

### 2.1 怎么用

- 直接输入 `/tk help` 可看完整语法；输入 `/tk status` 看总体状态。
- 输入**裸 `/tk`** 并回车（或从 `/` 菜单选择 `/tk`）会打开官方 `commandUi` 菜单。菜单是**只读语法目录**：
  - 首屏先给安全提示，再按域列出命令和可选参数；
  - 动态追加引用组、键名和 shell（最多 100 组 / 100 键 / 64 个 shell）；
  - 选中一项只会在输入栏上方显示完整语法，**不执行、不填草稿、不打开面板**；
  - 选择后裸 `/tk` 会被消费掉，焦点回到输入栏；照着提示手输完整命令再回车。
- `/tk <domain> <verb> …` 由宿主执行，例如 `/tk shell list`、`/tk vault group list`；命令文本和结果都会进入 DSH 的命令/会话记录。
- `/tk` 是**会话命令**：在已有会话的输入栏执行。全新草稿页的菜单提示可用，但发送 `/tk …` 不会执行；先发送一条消息建立会话。
- 没有官方 `commandUi` 的 CLI/TUI 或客户端里，菜单不启用；裸 `/tk` 会直接执行宿主命令并返回 `/tk help` 文本。

### 2.2 命令一览

下面省略开头的 `/`；实际在输入栏输入 `/tk …`。

```text
tk help
tk status

# 引用库：组
tk vault group list
tk vault group create <name> [--mode none|obfuscate|passphrase] [--passphrase-file PATH] [--no-persist]
tk vault group mode <name> none|obfuscate|passphrase [--passphrase-file PATH]
tk vault group persist <name> on|off
tk vault group rename <old> <new>
tk vault group delete <name> [--cascade] --yes
tk vault group unlock <name> [--passphrase-file PATH]
tk vault group lock <name>

# 引用库：键
tk vault key list [--group NAME]
tk vault key get <key> [--group NAME] [--to-file PATH --yes]
tk vault key set <key> [--group NAME] --value-file PATH [--note TEXT] [--max-uses N] [--expires-at ISO] [--kind TYPE] [--reuse]
tk vault key move <key> --from <group> --to <group>
tk vault key delete <key> [--group NAME] --yes

# shell 生命周期
tk shell list
tk shell show <id>
tk shell new [--label NAME] [--cwd PATH] [--cols N] [--rows N] [--idle-minutes N] [--from ID]
tk shell rename <id> <new-label>
tk shell resize <id> <cols> <rows>
tk shell close <id> --yes
tk shell lock <id> [--note TEXT]
tk shell unlock <id>
tk shell snapshot <id>
tk shell snapshot-list

# 看门狗
tk watchdog status
tk watchdog set [--enabled on|off] [--grace-ms N] [--renew-ms N] --yes
tk watchdog start|stop|restart --yes

# 设置
tk settings list
tk settings get <key>
tk settings set <key> <value> [--yes]

# 审计
tk audit files
tk audit chain
tk audit notices [--limit N]

# 宏
tk macro list
tk macro set <key> --text-file PATH [--scope conversation|global|shell] [--session ID] [--no-submit] [--note TEXT]
tk macro remove <key> --yes

# 工作区
tk workspace list
tk workspace save <name> [--sessions id1,id2|*]
tk workspace restore <name>
tk workspace delete <name> --yes
```

### 2.3 安全约束

- 秘密值、口令和宏内容**不得**写在命令行；分别只通过 `--value-file`、`--passphrase-file`、`--text-file` 读取，文件必须 **0600**。上限：值 16 KiB、口令 4 KiB、宏 8 KiB。
- `key get` 默认只返回元数据；导出值必须 `--to-file PATH --yes`。目标文件必须**尚不存在**（不会被覆盖），写入后权限 0600，值不会打印到命令结果。
- `--yes` 用于删除组/键、级联删除、看门狗启停/参数、`key get --to-file`，以及修改安全相关设置。
- 组规则：
  - **默认组**不可改名、不可删除、不可单独改加密方式或落盘属性；默认组级联删除会先被拒绝，不会先删键。
  - 非空组只有加 `--cascade` 才能连键一起删除；普通删除要求组为空。
  - 加密/混淆组**不能**切换落盘属性（需先改回 `none`），也**不能**改名（避免降级明文）；不落盘组同样不能改名。
  - 锁定组不能改名、改加密方式、改落盘属性，也不能移入/移出键；先 `unlock`。
  - 口令组 `unlock` 需要 `--passphrase-file`；简单混淆组不需要口令。`--mode passphrase`（创建或改模式）也必须同时给 `--passphrase-file`。解锁失败在 60 秒内累计 5 次会被限速。
- 键重建：名字曾被销毁（烧伤）时，新建同名键要加 `--reuse`。`--max-uses -1` 表示不限次数，`1` 表示一次性；`--expires-at` 接受 ISO 时间或毫秒时间戳；`--kind` 默认 `secret`。
- 设置：`settings list` 只显示允许通过 `/tk` 读写的键；`settings get/set` 对白名单外的键直接拒绝，安全相关键需要 `--yes`。
- 语法是“名词 + 动词 + 长选项”，支持单/双引号和 `--` 结束选项；命令上限 4096 字符/128 词，未知选项、缺值、重复选项都会明确报错，不会降级成普通提示词。

### 2.4 安全边界（必须知道）

- 宿主 `/tk` 的**命令文本和结果**会进入 DSH 的命令/会话记录，AI 可能看到命令参数、文件路径、键名和备注。
- **功能是面板的子集**：列表筛选、批量操作、锁与接管、快照预览、引用库编辑/解锁、宏与工作区管理、审计详情、设置页等仍以面板为主。
- **不适合长任务和交互**：长输出、TUI、实时进度、并发操作请用面板或模型工具；纯文本结果不便于回看和筛选。
- 写入秘密时绝不能把值放进命令行；命令正常不会打印值，但“文件路径”可见。
- `/tk` 是**给人用的输入栏接口，不是模型工具**：AI 不能通过工具调用直接执行 `/tk`，但它能读到会话里的命令与结果，也可能以同一 OS 用户读取文件。插件不把 `/tk` 当操作系统隔离。
- 如果连文件路径都不允许 AI 看到，纯文本宿主命令无法满足；应改用不进入会话的客户端安全输入或独立凭据服务。
- 当前交互入口是 Web 输入栏；headless 是一次性任务，没有输入栏。任何提供 `ctx.commands` 的 TUI/CLI 适配器都能复用同一语法；`lib/tk-command.mjs` 只做解析，不依赖 Web。

## 3. 键位

> 当前为固定绑定；自定义键位在规划中。焦点不在面板时，按键照常交给终端。

面板快捷键：

| 动作 | 默认键 |
|---|---|
| 新建 shell | `Ctrl+Shift+T` |
| 关闭当前 shell | `Ctrl+Shift+W` |
| 上一个 / 下一个 shell | `Ctrl+Shift+↑ / ↓` |
| 跳到第 N 个 shell | `Ctrl+Shift+1…9` |
| 会话选择器 | `Ctrl+Shift+P` |
| 详情 | `Ctrl+Shift+D` |
| 引用库 | `Ctrl+Shift+K` |
| 日志管理 | `Ctrl+Shift+L` |
| 锁定 / 解锁 | `Ctrl+Shift+M` |
| 重命名当前 shell | `F2` |
| 面板内搜索 | `Ctrl+F` |
| 关闭浮层 | `Esc` |

终端键位与 tmux 直通（`^b` 前缀等）不改动；完整三组键位表在面板「详情 → 键位帮助」。

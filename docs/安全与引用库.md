## 1. 先说清楚：它不是沙箱

terminalkeeper 给 AI 的是**你本人权限下的真实 shell**。它不是受限执行环境：

- AI 拿到写工具后，能以你的用户权限读写文件、跑命令；
- 危险命令拦截只是启发式减速带，能绕过，也会误报；
- 默认没有逐条审批，第一次使用某个对话时确认一次；
- 审计链能发现改动，但不是不可篡改（除非加内核级只追加锁）。

所以：**不要把不可替代的数据、生产环境或高价值凭据放在一个你准备交给 AI 的机器上。**

<a id="p1-2"></a>
## 2. 锁、模式闸门与审计

- **不做对话授权**：插件没有授权页面、默认授权规则或按会话授权；工具是否可用只由 DSH 沙箱模式决定。
  完全控制（`danger-full-access`）下写工具直接可用；工作区/只读模式下改动类工具被模式闸门拒绝，
  只读工具（`shell_state` / `shell_read` / `shell_audit`）始终可用。
- **人机互斥**：人在面板里操作某个 shell 时，AI 对它的写操作会让位；只读不受影响。
- **锁**：AI 没有 `lock/unlock` 动作；只有人在面板里操作。
- **审计链**：每次输入、开关会话、改名、宏和引用库操作都会进 SHA-256 封链；删除前也先记一条。
  有签名检查点，可导出审计文件，也可选异地镜像。
- **诚实边界**：审计是“事后查得清”，不是“证明没被改过”。同权限进程能改审计文件；
  要内核级只追加，运行 `./install-deps.sh --audit-lock`（`chattr +a`），但它仍不防读取。

<a id="p1-3"></a>
## 3. 引用库怎么保护秘密

引用库（vault）是给人存密码、令牌等短秘密的地方，AI 只能引用键名。

- **三种模式**：不加密 / 简单混淆 / 口令加密。
  - 默认组是**不加密**，方便开箱使用；要保护秘密请新建口令组。
  - 简单混淆只用设备密钥，主要防明文落盘，不是保密机制。
  - 口令组用 `scrypt` 加设备 pepper：
    `KEK = HMAC-SHA256(pepper, scrypt(口令, salt))`。
    `pepper` 是 32 字节随机值，存在 `vault.pepper`，和 `vault.json` 分文件。
- **只泄露 vault.json 时**：攻击者没有 pepper，无法离线猜口令。
- **pepper 丢失**：口令组会拒绝解锁，不会静默生成新 pepper；备份时必须把
  `vault.pepper` 和 `vault.json` 一起保存。
- **落盘**：一组秘密就是**一整段密文**，键名、值、次数、备注都在密文内；AAD 绑定组名和代数，
  不能把密文搬到别的组；加密前做**分桶填充**，密文长度和条目数不可知；计数取文件与内存的
  **max(** 值，单侧回滚不会让次数变小；销毁只留不透明 `entryId` 和名字指纹（烧伤标记），
  不留明文键名；状态头保存单调 **seq** 和指纹，能判断回滚/篡改/缺头，判定与写入都是 **O(1)**。
- **额度**：单值 16 KiB；总键数 2000、每组 500、明文总量 5 MiB；剩余次数归零即焚。
- **诚实边界**：pepper 和 `vault.json` 在同一个数据目录，同权限 AI 能读整个目录时，
  pepper 不构成安全边界；它只防“只拿到 vault.json / 只备份了密文文件”的离线暴力破解。

<a id="p1-4"></a>
## 4. AI 能做什么、不能做什么

- AI 只能做**整条裸引用**：整条输入就是 `{{v:键名}}`，典型用法是喂给 `read -s`、`sudo -S`
  这类标准输入提示。
- **嵌进命令会被拒绝**：`echo`、管道、`curl -H "…{{v:key}}"` 等不会发送，避免值进入 AI
  可加工的管线。
- AI **不能**通过宏间接引用 vault；人创建的宏里含 vault 时，AI 展开会被拒。
- `shell_manage action=vault-list` 只给键名、类型和额度，不给值。
- 面板列表也不返回值；要看/复制某个值必须单键读取，并写一条 `read-value` 审计。
- 同源页面仍可以逐个读取，只是从“一次拉全”变成多次可审计请求；这是诚实的限制。

<a id="p1-5"></a>
## 5. 明确防不住什么

- **同权限进程**（包括 AI 的 shell）可以直接读 `vault.json`、`vault.pepper` 和 `output/` 留痕；
  0600 只挡别的用户。
- **值进了终端就会进留痕**：`output/` 是原始字节流，打码只覆盖引用注入产生的行；
  程序自己打印的明文按已泄露处理。
- **转换外泄防不住**：`base64`、`rev`、`od` 等变换后会绕过字面打码。
- **裸引用不是保密边界**：把值喂给会回显的程序（如 `cat`）仍会出现在屏幕上。
- **AI 被 prompt injection 控制时**，它可以用 shell 工具做任何该用户能做的事；
  真正的隔离要靠独立用户、容器或另一台机器，插件本身做不到。
- 敏感信息脱敏是形状匹配，输出里的占位符是 `redacted`；它不是完整的秘密识别器。

<a id="p1-6"></a>
## 6. 报告安全问题

请不要在公开 issue 里贴可利用载荷、凭据、内网地址或完整日志。

优先用 GitHub 的 **Security → Report a vulnerability** 私有报告；说明 DSH 版本、
`tmux -V`、插件版本和受影响的工具或页面即可。确认后会在新版本里修复并说明影响范围。

**不得**把“显示打码”说成“防泄露”，也不得把状态头/审计链说成“不可篡改”；这些是实现约束，
也是用户需要知道的边界。

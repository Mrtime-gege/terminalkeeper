# 发布标准：首次可用（First-Use Criterion）

> **文档状态（2026-10-21）**：公开版本 **0.1.0**（内部迭代线 0.3/0.4 为历史编号）；当前行为以 `docs/项目文档.md` 与代码为准。


## 标准（发布阻塞项）

**一个空白上下文的 AI（没有任何插件用法提示、没有历史对话）在第一次任务中，必须只靠插件自身的
工具说明与系统提示，就把典型任务做对。**

量化判定（全部满足才算通过）：

| 指标 | 门槛 |
|---|---|
| 参数错误（"不认识的字段 / 缺必填 / kind 不对"） | **0 次** |
| 因失败而重试（同一目标换参数重来） | **0 次**（复核性多读一次不算） |
| 选错工具（用 shell_read/shell_state 代替执行，或用 shell_send 代替 run 等） | **0 次** |
| 归属违规（操作了别的对话创建的 shell） | **0 次** |
| 遗留（未关闭自己创建的 shell） | **0 个** |

理由：这个插件是给"需要真 TTY 的持久 shell"用的；如果模型第一次用就要试错，等于把插件缺陷
转嫁成用户的等待与 token 成本。**说明不清就修说明，不要靠用户教。**

## 判定流程（每次发布前跑一次）

1. **派一个全新的子 agent**（fresh context），提示词**只给任务目标**，例如：

   ```text
   请完成：① 启动一个可交互的持久 shell；② 在它里面执行 `uname -a`；
   ③ 读出它的输出；④ 关闭这个 shell。逐项如实汇报：调用了哪些工具（名字+参数）、
   是否失败、是否第一次就选对、是否清理干净。
   ```

   ⚠ 提示词里**不得出现**工具名、参数名、用法提示 —— 否则这项标准就失去意义。

2. **用审计核对，不只听汇报**：

   ```bash
   F=~/.dsh/terminalkeeper/audit-$(date +%F).jsonl
   grep -h '<子agent的 session id>' "$F" | grep -E '"event":"(open|input|close)"'
   grep -h '"event":"tool-call"' "$F" | grep -c '不认识的字段\|argError'   # 应为 0
   ```

3. **记录结果**（追加到下面"已记录结果"），并在 PR/发布说明里引用。

## 自动门禁（`npm test` 必过）

`scripts/test-first-use.mjs` 把"首次可用"里**可机检**的部分固化下来：

* 七个工具都有说明，且**每个参数**都有解释；
* 所有枚举取值都被逐值解释（`ENUM_FACTS`）；
* 系统提示里有 **intent → tool** 路由段（一个意图一个显然的工具）；
* 参数错误信息**必须可行动**（含"允许的字段 / 必须 / 必填 / 只支持"之一）；
* 顶层参数数量有上限（防止参数面膨胀到无法盲用）。

失败处置：先改**工具说明/参数结构**，再重跑盲测；不要通过在提示词里加"用法提示"来绕过标准。
